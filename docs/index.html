The decision currently open

One thing is waiting on a call, and it gates the security of every swap.

The BTC leg of a swap is not checked by consensus, so a miner can take an escrow without paying. Closing it means either atomic swaps or relaying BTC headers — and which one depends on whether the taker can run our software or must pay from any wallet.

Protocol documents

Long-form, illustrated, and the place where design decisions are argued out. Read them in this order if you are new.

Swap Mechanics docs/specs/SWAP_MECHANICS.html

How an L2 ↔ L1 swap works end to end. The boundary between block data and node-local observation, why there are two claim validators, and what the L1 leg still takes on faith.

 L1 Payment Proofsproposal docs/specs/L1_PAYMENT_PROOFS.html

Making the parent-chain half of a swap something every node checks rather than something each node takes on faith. Proof-carrying claims, a deterministic depth anchor, and three scope options.

 Proving the Parent Chainfor decision docs/specs/PARENT_CHAIN_VERIFICATION.html

Four ways to close the L1 gap for a BTC parent chain, given that our mainchain is eCash. Sequence diagrams for each, what they cost, and the one product question that decides between them.

 Swap Implementation Spec docs/specs/swap-implementation-spec.md

The original written specification for the swap subsystem: types, states, and the RPC surface.
